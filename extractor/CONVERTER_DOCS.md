# phaserOTBM_converter.py — Technical Documentation

Pipeline script that converts OTBM map data (via OTBM2JSON) into Phaser-compatible `map.json` + sprite assets.

---

## Pipeline Overview

```
.otbm file
    │
    ▼ (OTBM2JSON — node dump.js)
{MAP_NAME}.raw.json       ← OTBM nodes serialized as JSON
    │
    ▼ (phaserOTBM_converter.py)
{MAP_NAME}-sprites/
    ├── map.json           ← Phaser map definition
    └── sprites/           ← Copied sprite PNGs organized by appearanceId
         ├── 4427/
         │    └── 4427.png
         ├── 1128/
         │    ├── 1128_0.png
         │    └── 1128_1.png
         └── ...
```

---

## Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `TILE_SIZE` | `32` | Tile size in pixels — must match Phaser tilemap config |
| `MAP_NAME` | `"dragon-darashia"` | Map name — determines input/output paths |
| `OTBM_FILE` | `{MAP_NAME}.raw.json` | Raw JSON from OTBM2JSON |
| `ITEMS_SOURCES` | `sprites/items`, `sprites/missiles`, `sprites/` | Directories searched for sprite metadata JSONs and PNGs |
| `OUTPUT_DIR` | `{MAP_NAME}-sprites/` | Output directory for map.json and sprites |
| `ASSETS_ROOT` | `assets/{MAP_NAME}-sprites` | Path prefix for asset references in map.json |

To process a different map, change `MAP_NAME` at the top of the script.

## Sprite Metadata Source Files

Each appearance ID has a JSON metadata file (e.g., `sprites/items/4427/4427.json`) containing:

```json
{
  "id": 4427,
  "frame_group": [{
    "sprite_info": {
      "sprite_id": ["4427_0", "4427_1", ...],
      "patternWidth": 4,
      "patternHeight": 4,
      "patternDepth": 1,
      "layers": 1,
      "patternFrames": 0,
      "animation": null
    }
  }],
  "flags": {
    "bank": { "waypoints": 0 },
    "unpass": true,
    "unmove": true,
    "unsight": true,
    "automap": { "color": 114 },
    "fullbank": true
  }
}
```

These files are generated by the `read_aec.py` / `Appearances_pb2.py` pipeline from Tibia's `.aec` asset files.

## Core Functions

### `analyze_item(appearance_id: int) -> Dict`

Loads and analyzes a single item's metadata. Results are cached in `ITEM_CACHE`.

**Returns:**
```python
{
    "appearanceId": int,
    "type": "static" | "random" | "animated" | "unknown",
    "hasSprite": bool,
    "animated": bool,
    "random": bool,
    "animation": { ... } | None,
    "metadataFound": dict | None,       # raw metadata (sprite_ids stripped)
    "flags": {
        "fullbank": bool,
        "unmove": bool,
        "unpass": bool,
        "unsight": bool,
        "automap": bool,
        "bank": bool,
        "clip": bool,
        "bottom": bool,
        "top": bool,
        "hang": bool,
        "isRoof": bool,                 # legacy: unpass+unmove+unsight+automap+bank+bounding>=64
    },
    "spriteInfo": {
        "patternWidth": int,
        "patternHeight": int,
        "patternDepth": int,
        "boundingSquare": int,          # patternWidth * patternHeight * TILE_SIZE
    },
    "sprites": [
        {
            "spriteId": str,
            "sourcePath": str | None,
            "destPath": str,            # relative asset path for Phaser
            "destAbsPath": str,         # absolute path for file copy
            "width": int,
            "height": int,
            "available": bool,
        },
        ...
    ],
    "maxSpriteHeight": int,
    "issues": [str],                    # warnings: "missing_sprite:...", "metadata_missing", etc.
}
```

### `classify_layer(analysis: Dict) -> str`

Classifies an item into one of 5 rendering layers based on its metadata flags.

**Decision tree (order matters):**

```
1. flags.top = true              → "top"     (ceiling/overhead items)
2. flags.clip = true             → "border"  (terrain transition borders)
3. unpass + unmove + unsight      → "roof"    (sight-blocking structural)
4. flags.bottom = true           → "bottom"  (ground-level decorations)
5. fallback                      → "object"  (normal items, furniture, walls)
```

**Important:** This function classifies items within tiles. For `tileid` entries,
most go to the Ground tilelayer. However, **large blocking tiles** (those with
`unpass + unmove + unsight` and sprite size > 1×1) are reclassified as "roof"
and moved to the Roof objectgroup. This prevents 64×64+ sprites from being
rendered in a 32×32 tilelayer (which caused black lines and incorrect overlap
with clip/border sprites).

### `_is_roof_tile(analysis: Dict) -> bool`

Determines if a `tileid` should be redirected from ground to roof.

**Criteria:**
- Has all three blocking flags: `unpass + unmove + unsight`
- Sprite occupies more than 1×1 tile (`patternWidth > 1` or `patternHeight > 1`)

Tiles that are 1×1 (like void/black ID 101) stay in ground even if blocking.

### `build_phaser_map(dump: Dict) -> Dict`

Main conversion function. Takes raw OTBM2JSON output and produces Phaser map data.

**Algorithm:**
1. **First pass** — Iterate all OTBM nodes/features/tiles:
   - `tileid` → analyzed; if `_is_roof_tile()` returns true, stored in `raw_item_stacks` instead of `ground_tiles`; otherwise stored in `ground_tiles` dict
   - `items[].id` → analyzed and stored in `raw_item_stacks` for second pass
   - Track map bounds (`min_x`, `min_y`, `max_x`, `max_y`)
2. **Second pass** — Classify items into 5 objectgroup layers:
   - Uses `classify_layer()` to determine target layer
   - Builds `_make_object_entry()` with world pixel coordinates
3. **Build tilesets** — One tileset entry per unique appearance ID
4. **Build layers** — Ground tilelayer + up to 5 objectgroup layers

### Helper Functions

| Function | Purpose |
|----------|---------|
| `_get_layer_dict()` | Routes `layerClass` string to the correct objects dict |
| `_make_object_entry()` | Creates standardized stack entry with world coords, flags, layerClass |
| `ensure_sprite_assets()` | Copies sprite PNGs to output dir (idempotent via `COPIED_SPRITES`) |
| `resolve_sprite_path()` | Searches `ITEMS_SOURCES` dirs for a sprite PNG |
| `resolve_item_json_path()` | Searches `ITEMS_SOURCES` dirs for item metadata JSON |
| `get_png_dimensions()` | Reads PNG header to get width/height (cached) |
| `build_asset_path()` | Builds relative asset path for Phaser texture loading |

## Output Format — `map.json`

### Root Object

```json
{
  "version": 4,
  "orientation": "orthogonal",
  "renderorder": "right-down",
  "tilewidth": 32,
  "tileheight": 32,
  "width": 42,
  "height": 38,
  "bounds": { "minX": 795, "minY": 801, "maxX": 836, "maxY": 838 },
  "defaultZ": 7,
  "assetsRoot": "assets/dragon-darashia-sprites",
  "objectDefs": { ... },
  "sheets": { ... },
  "floors": { "7": { "z": 7, "layers": [ ... ] } },
  "tilesets": [ ... ],
  "animations": { ... }
}
```

(`floors`/`defaultZ` since ADR 0002; `sheets` + `objectDefs[id].sheet`/`.gids` since v4/ADR 0003.)

### Layers

**Ground (tilelayer):**
```json
{
  "id": 1,
  "name": "Ground",
  "type": "tilelayer",
  "visible": true,
  "opacity": 1,
  "width": 42,
  "height": 38,
  "data": [0, 0, 1, 1, 2, ...],
  "properties": { "depthOffset": 0, "layerClass": "ground" }
}
```

**Objectgroup layers (Borders, Bottom, WallsSouth, WallsEast, Objects, Top, Roof):**

Compact format — one array per placed tile, `[tileX, tileY, ...stackEntries]`, each stack entry
`[appearanceId, stackIndex]`. Every property that's the *same* for every placement of an
appearance (type, layerClass, sprite reference, flags, ...) lives once in the top-level
`objectDefs`, keyed by appearanceId — join `objectDefs[appearanceId]` with the stack entry to
reconstruct the full picture:

```json
{
  "id": 5,
  "name": "Objects",
  "type": "objectgroup",
  "visible": true,
  "objects": [
    [42, 3, [5557, 0]]
  ],
  "properties": { "depthOffset": 10, "layerClass": "object" }
}
```

```jsonc
// objectDefs["5557"]
{
  "type": "random",
  "layerClass": "object",
  "sheet": "object-32",
  "gids": [9, 10, 11],
  "random": true,
  "flags": { "unmove": true }
}
```

### `objectDefs` sprite reference — `sheet` + `gids` (map.json v4)

Since v4 (see `docs/adr/0003-map-json-v4-grid-sheets.md`), an `objectDefs` entry's sprite frames
are **not** individual PNG paths — they're `gids` (grid-cell indices) inside a shared `sheet`
(a key into the root `sheets` map). Resolve a frame's pixel rect with pure arithmetic:

```
col = gid % sheets[sheet].columns
row = gid // sheets[sheet].columns
x = col * sheets[sheet].cellWidth
y = row * sheets[sheet].cellHeight
```

An entry with no `sheet`/`gids` was only ever seen as a ground `tileid`, never placed via an
objectgroup — nothing looks it up dynamically, so it isn't worth packing into a sheet (see ADR
0003). (Static scenery baking, which used to leave some entries `"bakedOnly": true` with no sprite
reference, was removed — see "Bakedgroup layer — removed" below.)

**`ground`/`tilesets` did not change** — the tilelayer still resolves ground tile images through
the `tilesets` array exactly as in v3, one PNG per unique appearance ID. Only `objectDefs` sprites
moved to sheets.

### Root `sheets` field (map.json v4)

```jsonc
"sheets": {
  "object-32": {
    "image": "assets/rats-rookguard-sprites/sheets/object-32.png",
    "cellWidth": 32,
    "cellHeight": 32,
    "columns": 16
  }
}
```

One entry per `(layerClass, sizeBucket)` combination that had at least one placed appearance.
Bucket sizes are 32/64/128px, chosen by an appearance's largest side, rounded up to the nearest
bucket that fits it (see `extractor/scripts/sheet_packer.py`).

### Outfit atlases (monstros)

`monsters/<outfitId>/*.png` **não é mais gerado por mapa**. `bake_outfit_atlas.py` empacota os
frames de cada outfit em um atlas único, gerado uma vez em `extractor/atlases/outfits/<outfitId>.{png,json}`,
compartilhado por todos os mapas — `monsters/respawn.json` referencia esse atlas por outfit em vez
de ter sua própria cópia dos sprites. Ver `PHASER_MONSTERS.md` e `.scratch/outfit-sprite-atlas/`.

### Bakedgroup layer — removed

Static scenery used to be pre-composited offline into a `bakedgroup` layer (one PNG per `(tileY,
layerClass)`) instead of being placed as individual dynamic objects. Measured against the 8 real
maps, this produced 41-262 separate PNG requests per map — more than the 4-6 sheets that now cover
the same content — so it was removed entirely in favor of routing every dynamic appearance through
`sheet`+`gids` uniformly. See `docs/adr/0001-bake-unit-is-row-plus-layerclass.md` (superseded) and
`docs/adr/0004-remover-bake-usar-so-sheets.md`. There is no more `bakedOnly` field or `bakedgroup`
layer type — every `objectDefs` entry that isn't ground-only has `sheet`+`gids`.

### Tilesets

One tileset per unique appearance ID. Used by the Ground tilelayer.

```json
{
  "firstgid": 1,
  "name": "tile-101",
  "tilewidth": 32,
  "tileheight": 32,
  "tilecount": 1,
  "columns": 1,
  "image": "assets/dragon-darashia-sprites/sprites/101/101.png",
  "imagewidth": 32,
  "imageheight": 32
}
```

### Animations

Keyed by appearance ID. Only present for animated items.

```json
{
  "12345": {
    "appearanceId": 12345,
    "frames": ["assets/.../12345_0.png", "assets/.../12345_1.png"],
    "frameDurationMs": 500,
    "frameRate": 2,
    "loop": true,
    "startFrame": 0
  }
}
```

## Flag Reference

Flags extracted from Tibia's `Appearances.proto` metadata:

| Flag | Type | Rendering Impact |
|------|------|-----------------|
| `bank` | `{waypoints: int}` | Walkable surface; waypoints = ground speed (0 = blocked) |
| `fullbank` | `bool` | Covers entire tile visually |
| `clip` | `bool` | Sprite extends beyond tile boundaries (terrain borders) |
| `bottom` | `bool` | Renders above ground, below creatures/players |
| `top` | `bool` | Renders above everything (ceiling, overhead signs) |
| `unmove` | `bool` | Cannot be pushed/moved by players |
| `unpass` | `bool` | Blocks pathfinding / walking |
| `unsight` | `bool` | Blocks line of sight (occludes tiles behind/below) |
| `hang` | `bool` | Wall-hanging item |
| `automap` | `{color: int}` | Minimap color |
| `height` | `{elevation: int}` | Visual elevation offset |
| `light` | `{brightness, color}` | Emits dynamic light |
| `shift` | `{x, y}` | Pixel offset for rendering |

### Classification Rules

| Condition | Layer | Depth |
|-----------|-------|-------|
| `tileid` in OTBM (non-blocking or 1×1) | Ground (tilelayer) | 0 |
| `tileid` in OTBM (unpass+unmove+unsight, >1×1) | Roof (objectgroup) | +100 |
| `top = true` | Top (objectgroup) | +50 |
| `clip = true` | Borders (objectgroup) | +1 |
| `unpass + unmove + unsight` | Roof (objectgroup) | +100 |
| `bottom = true` | Bottom (objectgroup) | +5 |
| Everything else | Objects (objectgroup) | +10 |

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|---------|
| Black lines in tiles | 64×64 sprite in 32×32 tilelayer | Fixed: large blocking tileids are now objectgroups (roof) |
| Missing sprites | Source PNG not in `sprites/items/` | Check `[WARN]` output during conversion |
| Wrong positions | `worldX/worldY` not recalculated | Fixed: two-pass algorithm recalculates after bounds |
| Items overlapping | Wrong depth | Use `depthOffset` from layer properties |
| Roof always visible | Not toggled | Add visibility toggle on Roof layer images |
